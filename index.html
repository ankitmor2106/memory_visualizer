Packages & Imports

A Package groups related classes to prevent naming conflicts. Packages map to directory structures on disk.

package com.visualizer;
import java.util.List;

Classes & Objects

A Class is a blueprint defining state (fields) and behaviour (methods). An Object is a runtime instance allocated on the Heap.

class Car { String color; }
Car myCar = new Car(); // ref on Stack, object on Heap
Official Object docs ↗

Constructors

A Constructor initialises a new object. It is invoked by the new keyword, shares the class name, and has no return type.

Official Constructor docs ↗

Types of Variables

Primitives (int, double, boolean) store values directly on the Stack. Reference types store a memory address pointing to the Heap.

Official Data Types docs ↗

Methods & Scope

Each method call pushes a new frame on the Call Stack containing its local variables. Variables are destroyed when the frame is popped.

Official Method docs ↗

The Call Stack

A LIFO structure. Every method invocation pushes a frame storing local variables and the return address. Frame destruction is instant — no GC needed.

JVM Stack spec ↗

The Heap

Shared, dynamic memory where all objects and arrays live. Objects can outlive the method that created them; access is via references stored on the Stack.

JVM Heap spec ↗

Garbage Collection

When an object has zero reachable references, the Garbage Collector marks it for deletion, freeing Heap memory without programmer intervention.

Official GC Guide ↗

Pass-by-Value

Java is strictly pass-by-value. When passing an object, you copy the reference value (address). The method can mutate Heap data but cannot reassign the caller's variable.

Variables & Types

Python is dynamically typed — variables are names (labels) pointing to objects. Types are attached to objects, not variables.

x = 42        # int object on the heap
name = "Ada"  # str object on the heap
x = 3.14      # x now points to a new float
Official Built-in Types ↗

Functions & Scope (LEGB)

Python uses LEGB scope: Local → Enclosing → Global → Built-in. Each call creates a new frame. Use global or nonlocal to escape local scope.

Execution Model ↗

Classes & Objects

Everything in Python is an object. __init__ initialises instance attributes. self is an explicit reference to the current Heap-allocated instance.

Official Classes docs ↗

Lists, Dicts & Sets

list — ordered, mutable. dict — key-value, insertion-ordered (3.7+). set — unordered, unique. tuple — immutable. All heap-allocated.

Sequence Types ↗

The Call Stack

Python maintains a stack of frame objects. Each call pushes a frame holding locals, code, and the instruction pointer. Deep recursion raises RecursionError.

Frame Objects ↗

Heap & Object Model

All Python objects — including integers and strings — live on the heap. CPython uses a private memory manager with pools of fixed-size blocks for small objects.

Memory Management ↗

Garbage Collection

CPython uses reference counting as its primary GC strategy. A cyclic GC handles reference cycles that reference counting alone cannot break.

gc module ↗

Pass-by-Object-Reference

Python passes the reference value (pointer to the heap object). Mutating a mutable argument affects the original. Reassigning only changes the local binding.

var / let / const

var is function-scoped and hoisted. let and const are block-scoped with a temporal dead zone. Prefer const by default.

const PI = 3.14;   // block-scoped, immutable binding
let count = 0;     // block-scoped, mutable
var legacy = true; // function-scoped, avoid
MDN — Declarations ↗

Closures

A closure retains access to its enclosing lexical scope even after that scope has returned. Used for data privacy and factory functions.

function counter() {
  let n = 0;
  return () => ++n; // closes over n
}
MDN — Closures ↗

Classes & Prototypes

JavaScript is prototype-based. class syntax is sugar over prototype chains. Every object has a [[Prototype]] link used for property lookup.

MDN — Classes ↗

Call Stack & Event Loop

JavaScript is single-threaded. Async callbacks queue in the Task/Microtask Queue. The Event Loop moves them to the stack only when it is empty.

MDN — Event Loop ↗

Scope & Hoisting

var declarations and function declarations are hoisted to the top of their scope. let/const are hoisted but not initialised (temporal dead zone).

MDN — Hoisting ↗

Heap Memory

Objects, arrays, closures, and functions are allocated on the V8 Heap, divided into young generation (short-lived) and old generation (survived GC cycles).

V8 — Trash Talk ↗

Garbage Collection

Modern JS engines use mark-and-sweep with generational and incremental marking. An object is collectible when unreachable from any root.

MDN — Memory Management ↗

Primitives vs References

Primitives are copied by value. Objects and arrays are copied by reference — two variables can point to the same heap object.

Variables & Primitive Types

C++ is statically typed. Core types: int, long, float, double, bool, char. Use auto for type inference.

int age = 25;
double pi = 3.14159;
auto name = std::string("Alice");
cppreference — Types ↗

Pointers & References

A pointer (T*) stores an address and can be null. A reference (T&) is an alias — must be initialised, cannot be null or rebound.

int x = 10;
int* ptr = &x;  // pointer to x
int& ref = x;   // reference (alias) to x
*ptr = 20;      // modifies x via pointer
cppreference — Pointer ↗

Dynamic Memory (new / delete)

new allocates on the heap. delete frees it. Forgetting to delete causes a memory leak. Modern C++ uses smart pointers instead.

int* p = new int(42); // heap allocation
delete p;             // manual free
p = nullptr;          // prevent dangling pointer
cppreference — new ↗

Stack vs Heap

The Stack is automatic — local vars are deterministically destroyed. The Heap is manual/smart-pointer managed and can grow much larger.

Storage duration ↗

Classes & Structs

struct members are public by default; class members are private. Use struct for plain data carriers.

cppreference — Class ↗

RAII

Resource Acquisition Is Initialisation: tie resource lifetime to object lifetime. Acquire in the constructor; release in the destructor. Guaranteed cleanup even on exceptions.

cppreference — RAII ↗

Smart Pointers

unique_ptr — sole ownership, zero overhead. shared_ptr — shared via reference counting. weak_ptr — non-owning, breaks cycles.

auto p = std::make_unique<int>(42);
auto s = std::make_shared<Dog>("Rex");
cppreference — unique_ptr ↗

Templates

Templates enable generic programming. The compiler generates a concrete version at compile time for each type used (template instantiation).

template<typename T>
T add(T a, T b) { return a + b; }
