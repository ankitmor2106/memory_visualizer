1. Packages & Imports

A Package groups related classes to prevent naming conflicts and control access. Packages map directly to directory structures on disk.

package com.visualizer;
import java.util.List;

2. Classes & Objects

A Class is a blueprint defining state (fields) and behaviour (methods). An Object is a runtime instance allocated on the Heap.

class Car { String color; }
Car myCar = new Car(); // reference on Stack, object on Heap

3. Constructors

A Constructor initialises a new object. It is invoked automatically by the new keyword, shares the class name exactly, and has no return type.

Official Constructor docs ↗

4. Types of Variables

Java is statically typed. Primitives (int, double, boolean, char) store values directly in the Stack. Reference types (String, arrays, objects) store a memory address pointing to the Heap.

Official Data Types docs ↗

5. Methods & Scope

Each method call pushes a new frame on the Call Stack containing its local variables. Variables have local scope — they cease to exist when the frame is popped.

Official Method docs ↗

6. Access Modifiers

public — visible everywhere. private — visible only within the declaring class. protected — visible in the same package and subclasses. default (no keyword) — package-private.

Official Access Modifier docs ↗

7. Core OOP Concepts

Inheritance (extends) promotes code reuse. Polymorphism lets one interface represent multiple underlying types. Encapsulation hides internal state behind getters/setters.

Official OOP Concepts docs ↗

8. The Call Stack

A LIFO structure. Every method invocation pushes a frame storing local variables and the return address. When the method returns, its frame is instantly destroyed — no garbage collection needed.

JVM Stack specification ↗

9. The Heap

Shared, dynamic memory where all objects and arrays live. Objects can outlive the method that created them. Access is via references stored on the Stack.

JVM Heap specification ↗

10. Garbage Collection

The JVM automatically reclaims Heap memory. When an object has zero reachable references, the Garbage Collector marks it for deletion, freeing memory without programmer intervention.

Official GC Tuning Guide ↗

11. Pass-by-Value

Java is strictly pass-by-value. When passing an object, you copy the reference value (address). The method can mutate the object's Heap data but cannot reassign the caller's variable.

1. Variables & Types

Python is dynamically typed — variables are names (labels) that point to objects. Types are attached to objects, not variables. Core built-in types include int, float, bool, str, NoneType, list, dict, set, and tuple.

x = 42        # int object on the heap
name = "Ada"  # str object on the heap
x = 3.14      # x now points to a new float object
Official Built-in Types docs ↗

2. Functions & Scope

Python uses LEGB scope resolution: Local → Enclosing → Global → Built-in. Each function call creates a new frame on the call stack. Variables declared inside a function are local by default; use global or nonlocal to break out of that scope.

def greet(name):
    msg = f"Hello, {name}!"  # local scope
    return msg
Official Execution Model (Scope) docs ↗

3. Classes & Objects

Everything in Python is an object. Classes are defined with class. The __init__ method initialises instance attributes. self is an explicit reference to the current instance stored on the Heap.

class Dog:
    def __init__(self, name):
        self.name = name  # stored in instance __dict__
d = Dog("Rex")
Official Classes docs ↗

4. Lists, Dicts & Sets

list — ordered, mutable, allows duplicates. dict — key-value pairs (hash map), ordered by insertion since Python 3.7. set — unordered, mutable, unique values. tuple — ordered, immutable. All are heap-allocated objects.

Official Sequence Types docs ↗

5. Comprehensions

A concise syntax for creating collections. List, dict, and set comprehensions produce new objects on the Heap. Generator expressions are lazy — they produce values on demand without building the full collection in memory.

squares = [x**2 for x in range(10)]  # list comp
even_sq = {x: x**2 for x in range(10) if x % 2 == 0}
Official Comprehensions docs ↗

6. Exception Handling

Exceptions are objects derived from BaseException. try/except/else/finally provides structured error handling. Raising an exception unwinds the call stack frame by frame until a matching handler is found, or the program terminates.

try:
    result = 10 / 0
except ZeroDivisionError as e:
    print(f"Caught: {e}")
finally:
    print("Always runs")
Official Exceptions docs ↗

7. Modules & Imports

A module is a file containing Python definitions. import loads a module into the current namespace. Python caches modules in sys.modules so they are only executed once. Packages are directories with an __init__.py.

Official Modules docs ↗

8. The Call Stack

Python's interpreter maintains a call stack of frame objects. Each function call pushes a new frame (holding locals, the code object, and the instruction pointer). Frames are accessible via sys._getframe(). Deep recursion raises RecursionError when the default limit (1000) is exceeded.

Official Frame Objects docs ↗

9. Heap & Object Model

All Python objects — including integers and strings — live on the heap. CPython uses a private memory manager with pools of fixed-size blocks for small objects (under 512 bytes). Immutable types like str and int are often interned (shared) for efficiency.

Official Memory Management docs ↗

10. Garbage Collection

CPython uses reference counting as its primary GC strategy — each object tracks how many references point to it and is freed when the count hits zero. A cyclic GC (the gc module) handles reference cycles that reference counting alone cannot break.

Official gc module docs ↗

11. Pass-by-Object-Reference

Python passes the reference value (pointer to the heap object) — not the object itself, not a copy. Mutating a mutable argument (e.g. a list) inside a function affects the original. Reassigning the parameter only changes the local binding, not the caller's variable.

1. var / let / const

var is function-scoped and hoisted. let and const are block-scoped and not initialised until their declaration (the temporal dead zone). Prefer const by default; use let when reassignment is needed.

const PI = 3.14;      // block-scoped, immutable binding
let count = 0;        // block-scoped, mutable
var legacy = true;    // function-scoped, avoid
MDN — Variable declarations ↗

2. Functions & Closures

A closure is a function that retains access to variables from its enclosing lexical scope even after that scope has returned. This is a core JavaScript pattern used for data privacy and factory functions.

function counter() {
  let n = 0;
  return () => ++n; // closes over n
}
const inc = counter();
inc(); // 1, inc(); // 2
MDN — Closures ↗

3. Classes & Prototypes

JavaScript is prototype-based. class syntax (ES6+) is syntactic sugar over prototype chains. Every object has a hidden [[Prototype]] link used for property lookup. extends sets up prototype chaining for inheritance.

class Animal {
  constructor(name) { this.name = name; }
  speak() { return `${this.name} makes a sound`; }
}
class Dog extends Animal {
  speak() { return `${this.name} barks`; }
}
MDN — Classes ↗

4. Arrays & Objects

Arrays are indexed, heap-allocated objects with numeric keys. Plain objects are key-value maps. Both are reference types — variables hold a memory address, not the data itself. Spread syntax (...) creates shallow copies.

MDN — Array ↗

5. Call Stack & Event Loop

JavaScript is single-threaded with one Call Stack. Async operations (timers, I/O, promises) are handled by Web APIs; their callbacks are queued in the Task Queue or Microtask Queue. The Event Loop moves callbacks onto the stack only when it is empty.

MDN — Event Loop ↗

6. Scope & Hoisting

Hoisting moves var declarations and function declarations to the top of their scope at compile time. let/const are hoisted but not initialised. Function expressions and arrow functions are not hoisted.

MDN — Hoisting ↗

7. Promises & Async/Await

A Promise represents a future value. async functions always return a Promise. await suspends the async function until the awaited promise settles, yielding execution back to the event loop without blocking the call stack.

MDN — Using Promises ↗

8. Modules (ESM)

ES Modules (import/export) have static structure — imports are resolved at parse time. Each module has its own scope. The runtime builds a module graph, evaluates modules in dependency order, and caches them.

MDN — ES Modules ↗

9. Heap Memory

Objects, arrays, closures, and functions are allocated on the V8 Heap (or SpiderMonkey, JSC etc.). The heap is divided into spaces: young generation (short-lived objects) and old generation (objects that survived several GC cycles).

V8 — Trash Talk (GC deep dive) ↗

10. Garbage Collection

Modern JS engines use a tracing / mark-and-sweep collector augmented with generational GC and incremental/concurrent marking to minimise pauses. An object is collectible when it is unreachable from any root (global scope, stack frame, DOM node).

MDN — Memory Management ↗

11. Primitives vs References

Primitives (number, string, boolean, null, undefined, symbol, bigint) are copied by value. Objects and arrays are copied by reference — two variables can point to the same heap object.

1. Variables & Primitive Types

C++ is statically typed with explicit type declarations. Fundamental types include int, long, float, double, bool, char, and void. Use auto (C++11) to let the compiler infer the type.

int age = 25;
double pi = 3.14159;
auto name = std::string("Alice"); // deduced as std::string
cppreference — Fundamental types ↗

2. Pointers & References

A pointer (T*) stores a memory address and can be reassigned or set to nullptr. A reference (T&) is an alias — it must be initialised at declaration, cannot be null, and cannot be rebound. Prefer references when aliasing is sufficient.

int x = 10;
int* ptr = &x;   // pointer to x
int& ref = x;    // reference (alias) to x
*ptr = 20;       // modifies x via pointer
cppreference — Pointer ↗

3. Dynamic Memory (new / delete)

new allocates on the heap and returns a pointer; delete frees it. Failing to delete causes a memory leak. Deleting a pointer twice is undefined behaviour. Modern C++ replaces raw new/delete with smart pointers.

int* p = new int(42);  // heap allocation
delete p;              // must free manually
p = nullptr;           // prevent dangling pointer
cppreference — operator new ↗

4. Stack vs Heap

The Stack is automatic — local variables are pushed when a function is called and popped when it returns (deterministic, fast). The Heap is manual / smart-pointer managed — objects persist until explicitly freed. Stack is limited in size; heap can grow much larger.

cppreference — Storage duration ↗

5. Classes & Structs

Both class and struct define user-defined types with fields and methods. The only difference is default access: struct members are public by default; class members are private. Use struct for simple data carriers.

struct Point { int x, y; }; // public by default
class Circle {
  double r;                  // private by default
public:
  double area() { return 3.14 * r * r; }
};
cppreference — Class declaration ↗

6. Constructors & Destructors

A constructor initialises an object when it is created. A destructor (~ClassName) runs when the object goes out of scope or is deleted — the ideal place to release resources. Together they underpin RAII.

cppreference — Destructor ↗

7. Inheritance & Polymorphism

Declare virtual functions with virtual to enable runtime dispatch via the vtable. Mark overrides with override (C++11). Use = 0 for pure virtual functions to create abstract base classes. Always use a virtual destructor in base classes.

cppreference — Virtual function ↗

8. RAII — Resource Acquisition Is Initialisation

Tie resource lifetime to object lifetime. Acquire resources in the constructor; release them in the destructor. This guarantees cleanup even when exceptions are thrown. std::lock_guard, std::fstream, and smart pointers are all RAII wrappers.

cppreference — RAII ↗

9. Smart Pointers

std::unique_ptr — sole ownership, zero overhead, non-copyable. std::shared_ptr — shared ownership via reference counting; freed when the last owner is destroyed. std::weak_ptr — non-owning observer that breaks reference cycles.

auto p = std::make_unique<int>(42); // auto-deleted
auto s = std::make_shared<Dog>("Rex");
cppreference — unique_ptr ↗

10. Templates

Templates enable generic programming — code that works with any type. The compiler generates a concrete version at compile time for each type used (template instantiation). Function templates, class templates, and variadic templates are all supported.

template<typename T>
T add(T a, T b) { return a + b; }
add(1, 2);       // int version generated
add(1.5, 2.5);  // double version generated
cppreference — Templates ↗

11. STL Containers

The Standard Template Library provides generic, highly optimised containers. std::vector — dynamic array. std::map / std::unordered_map — ordered / hash key-value. std::set — sorted unique values. All allocate on the heap internally.

cppreference — Containers library ↗
